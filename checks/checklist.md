# Задание: проверить сайт перед сдачей и исправить всё найденное

Ты сделал прототип сайта УрФУ. Теперь стань строгим проверяющим: твоя цель — найти всё, что может подвести на глазах у жюри, и исправить. Не верь себе на слово: каждую проверку выполняй по-настоящему (программой или вручную по шагам) и записывай результат.

## Как работать

1. Запусти сайт локально (`python -m http.server` или аналог) и проверяй именно его, а потом ещё раз — опубликованную версию на GitHub Pages.
2. Для автоматических проверок используй безголовый браузер (Playwright или Puppeteer), axe-core из локального файла, Lighthouse. Скрипты проверок положи в папку `checks/` — их можно будет запустить снова.
3. Идёшь по разделам по порядку. Нашёл проблему — исправь, перезапусти ту же проверку и убедись, что прошла. Только потом дальше.
4. Если что-то исправить нельзя (нет данных, ограничение браузера) — не скрывай, а запиши в отчёт с причиной.
5. В конце — отчёт по форме из раздела 18.

Критерий «готово» для каждого пункта: **проверено, результат записан, ноль проблем — или проблема записана с причиной**.

## 1. Честность данных

- [ ] Каждая цифра, дата, цена, адрес, телефон, название программы на сайте взяты из официального источника. Пройди по всем страницам и составь таблицу: что за данные → откуда → дата. Ничего «примерно» и «для красоты».
- [ ] Под каждой ценой, баллом, числом мест, суммой стипендии есть источник и год.
- [ ] Всё демонстрационное (расписание, личный кабинет, результаты примеров) подписано «Пример» или «Демо» прямо на экране, рядом с данными.
- [ ] Одни и те же числа совпадают везде: на главной, в каталоге, на странице «Концепция», в PDF, в видео, в письме жюри, в README («94 программы» — значит, везде 94).
- [ ] Даты актуальны на день сдачи: прошедшие события и сроки скрыты, «до приёма документов N дней» считается верно. Проверь, задав разные даты через `?date=` (или подменив `Date` в браузере): за день до события, в день события, на следующий день, 31 декабря → 1 января.
- [ ] Время считается по Екатеринбургу (UTC+5): поставь в браузере другой часовой пояс и проверь, что «сегодня» не съезжает.
- [ ] Фото — настоящие фото УрФУ с указанием источника; у каждого есть право на использование (открытый источник).

## 2. Ссылки и кнопки

- [ ] Робот обходит все страницы сайта от главной, переходя по всем ссылкам: ни одной 404, ни одной ссылки «#» без действия, ни одной пустой `href`.
- [ ] Робот нажимает каждую кнопку на каждой странице: у каждой есть заметный результат (что-то открылось, отфильтровалось, скопировалось, перешло). Ни одной «мёртвой» кнопки. Заглушки `alert`, `print`, «Поделиться» и «скопировать» перехватывай в тесте, чтобы они не вешали проверку.
- [ ] Все якорные ссылки (`#раздел`) ведут к существующему `id`, и раздел оказывается на экране (не под закреплённой шапкой).
- [ ] Внешние ссылки открываются в новой вкладке, имеют `rel="noopener"` и подпись для экранной читалки «(откроется в новой вкладке)». Проверь, что внешние адреса живые (код ответа 200 или 3xx).
- [ ] Ссылки с параметрами (`Program.html?id=…`, `Catalog.html?ege=…&my=240`, `Search.html?q=общага`, `Schedule.html?g=…`) открывают именно то состояние. Ссылка на неизвестный id, группу, аудиторию, пустой и мусорный параметр (`?id=abc`, `?my=-5`, `?q=<script>`) — понятное сообщение, а не пустой экран и не ошибка.
- [ ] Страница 404 открывается на любом несуществующем адресе и полезна (поиск, популярные ссылки).

## 3. Ошибки в консоли

- [ ] На каждой странице при загрузке — 0 ошибок и 0 предупреждений в консоли (кроме тех, что выдаёт сам браузер о своих расширениях).
- [ ] 0 ошибок после действий: смена роли, все фильтры каталога, сравнение, поиск, квиз до конца, расписание, поиск аудитории, панель для слабовидящих (все схемы), открытие и закрытие меню и модальных окон.
- [ ] 0 ошибок, когда localStorage запрещён (приватный режим, `file://`, исключение при обращении) — проверь подменой `localStorage`, который бросает исключение.
- [ ] 0 ошибок при открытии через `file://` (двойной щелчок по `index.html`) и всё основное работает без интернета.
- [ ] 0 ошибок при отключённом JavaScript: страница не падает, основное содержимое видно, ссылки работают.

## 4. Вёрстка на всех ширинах

- [ ] Проверь ширины: 320, 360, 375, 390, 414, 600, 768, 820, 1024, 1280, 1366, 1440, 1920, 2560 px — на каждой странице. Сделай снимки экрана и просмотри их.
- [ ] Ни на одной ширине нет прокрутки вбок: `document.documentElement.scrollWidth <= innerWidth` на каждой странице и в каждом состоянии (открытое меню, модальное окно, широкая таблица, длинный поиск).
- [ ] Ничего не перекрывается и не обрезается: заголовки, кнопки, бейджи, повёрнутые наклейки, декоративные фигуры не наезжают на текст и не закрывают кнопки.
- [ ] Самые длинные слова и названия («Лингвистика в сфере деловых и профессиональных коммуникаций и информационных технологий», «Международные», «Энерго- и ресурсосберегающие») не вылезают за край на 320 px.
- [ ] Гигантские заголовки и цифры влезают на 320 px.
- [ ] Альбомная ориентация телефона (844×390): первый экран и меню не ломаются.
- [ ] Увеличение в браузере 200% и 400%: ничего не обрезается, нет прокрутки вбок, всё можно прочитать и нажать.
- [ ] Увеличенный шрифт по умолчанию (настройка браузера «очень крупный», 24 px): вёрстка держится.
- [ ] Нижнее меню телефона не закрывает последние элементы страницы и ссылки внизу экрана.
- [ ] Высота экрана на телефоне: первый экран не прячется под адресной строкой (`svh`/`dvh`).

## 5. Ничего не прыгает

- [ ] CLS при загрузке каждой ключевой страницы меньше 0,1 (цель 0,02). Меряй PerformanceObserver на медленной сети.
- [ ] **Прыжки при действиях.** Для каждого действия запиши положение и высоту соседних блоков до и после и убедись, что ничего, кроме самого блока, не сдвинулось без причины:
  - смена роли на главной;
  - движение ползунка баллов от минимума до максимума с шагом 1 (результат меняет текст: «1 программа / 2 программы / 5 программ / …бюджетное место / места / мест» — высота карточки не должна меняться ни на одном значении);
  - каждый фильтр каталога и их сочетания;
  - ввод в поиск по одной букве;
  - переключение недель в расписании;
  - открытие и закрытие подсказок поиска, аккордеонов, панели для слабовидящих.
- [ ] Шрифты: при загрузке текст не прыгает при подмене запасного шрифта на свой (сравни снимки до и после загрузки шрифта).
- [ ] Фото: у каждого есть размеры, место под фото зарезервировано заранее.

## 6. Анимации

- [ ] Все анимации идут ровно (без рывков) на компьютере и при замедлении процессора в 4 раза: запиши профиль производительности при прокрутке всей главной, кадры не дольше 16–20 мс, нет длинных задач больше 50 мс во время прокрутки.
- [ ] Анимируются только `transform`, `opacity`, `filter`, цвет; нет анимации размеров и положения через `top/left/width/height/margin`.
- [ ] `prefers-reduced-motion: reduce` (эмуляция в DevTools): движения нет вообще — ни параллакса, ни бегущих строк, ни счётчиков, ни смены цвета фона по прокрутке. Всё содержимое на месте и читается.
- [ ] Без JavaScript и при ошибке скрипта всё содержимое видно (ничего не осталось прозрачным или сдвинутым за экран).
- [ ] Печать (`Ctrl+P`, предпросмотр): всё содержимое видно, нет пустых мест на месте анимированных блоков, нет меню и нижней панели.
- [ ] Счётчики цифр: в HTML итоговое число; снимок экрана в любой момент анимации, при reduced-motion и без JS показывает правильное число (никаких «1816 год основания» вместо 1920).
- [ ] Ничего не мигает чаще 3 раз в секунду.
- [ ] Есть кнопка паузы для всего, что движется дольше 5 секунд; при наведении бегущие строки останавливаются.
- [ ] Бесконечные анимации на паузе, когда вкладка скрыта и когда блок вне экрана.
- [ ] Закреплённые блоки с горизонтальной лентой: доходят до конца ленты, отпускают прокрутку, не застревают; на телефоне свайп работает и не конфликтует с вертикальной прокруткой.
- [ ] Прокрутка колесом, тачпадом, клавишами (Пробел, PageDown, стрелки, Home/End) работает как обычно, ничего не перехвачено.
- [ ] Переходы между страницами не ломают кнопку «Назад» и положение прокрутки при возврате.

## 8. Доступность — вручную

- [ ] **Только клавиатура**: пройди главную, каталог (фильтры, сравнение, закрытие), страницу программы, поиск, расписание, квиз, поиск аудитории, панель для слабовидящих — без мыши. Всё доступно, порядок Tab логичный, нет ловушек фокуса, Esc закрывает окна и меню.
- [ ] Фокус всегда виден, на любом фоне (на ярких цветных секциях тоже) — контраст обводки к фону не меньше 3:1.
- [ ] После закрытия модального окна фокус возвращается на кнопку, которая его открыла.
- [ ] Ссылка «Перейти к содержимому» видна при фокусе и работает.
- [ ] Экранная читалка (NVDA или VoiceOver) на главной и в каталоге: заголовки по порядку, у всех кнопок и значков понятные названия, изменения результатов объявляются («Найдено 43 программы»), картинки описаны или скрыты как декоративные.
- [ ] **Контраст каждой пары цветов**: составь таблицу всех сочетаний текста и фона на сайте, включая наведение, фокус, нажатое и неактивное состояние, белый текст на каждом ярком фоне, цветной текст на каждом светлом фоне, текст поверх фото и градиентов (в самой светлой точке). Обычный текст — от 4.5:1, крупный текст и значки — от 3:1.
- [ ] Цели нажатия: на телефоне не меньше 44×44 px, на компьютере не меньше 24×24 px, и между соседними целями достаточно места.
- [ ] Формы: у каждого поля видимая подпись, ошибка написана текстом рядом с полем и связана с ним, обязательные поля отмечены, автозаполнение (`autocomplete`) где уместно.
- [ ] **Версия для слабовидящих**: каждая цветовая схема на каждой странице перекрашивает всё, включая цветные шапки, яркие секции, градиенты, бейджи, ленты, кнопки, нижнее меню. Ни один блок не остался в фирменных цветах. Крупный шрифт не ломает вёрстку. Настройки сохраняются при переходе между страницами. «Обычный вид» возвращает всё.
- [ ] Масштаб страницы не запрещён (`user-scalable=no` и `maximum-scale=1` отсутствуют).

## 9. Скорость

- [ ] Lighthouse в режиме телефона (медленный 4G, процессор ×4), по 3 прогона, берём медиану, на страницах: главная, поступление, каталог, программа, общежития, расписание, поиск, концепция. Скорость от 90, доступность 100, рекомендации 100, поисковая оптимизация 100.
- [ ] LCP не больше 2,5 с на каждой (цель до 2 с), CLS меньше 0,1, TBT меньше 200 мс.
- [ ] Вес обычной страницы до 500 КБ со всем, что грузится на первом экране; общий вес главной при прокрутке до конца — запиши.
- [ ] Нет скриптов и стилей, блокирующих отрисовку без нужды; свой JS с `defer`.
- [ ] Фото в WebP/AVIF подходящего размера (не грузим 3000 px для карточки 400 px), `srcset` для крупных фото, `loading="lazy"` для всего ниже первого экрана, `fetchpriority="high"` для главного фото.
- [ ] Шрифты: только нужные начертания, только кириллица и латиница, woff2, предзагрузка шрифта первого экрана.
- [ ] PageSpeed Insights (pagespeed.web.dev) для опубликованного сайта: сохрани ссылки на отчёты и цифры.
